**不在这个包里、也无法从本机恢复的：**
- `aihot` 库 **2026-10-14 08:00 之后**的数据（文章、精选、报告、订阅、后台操作等）。
  服务器根盘已随 Pod 重建丢失；`/root` 下 11-02、11-04 的预部署 dump 也一并丢失。
  11-04 生产记录是 **644 篇文章 / 26 个信源**，这份 dump 是 **358 篇 / 26 个信源**，
  中间约 **286 篇**没有找回来。
- 生产 `.data/uploads` 里的附件/图片（10-14 之后新上传的部分）。
- 除非腾讯云 COS 的 `daily/` 前缀里有备份，或云平台保留了 11-12 之前的快照；
  这两条需要人工去控制台确认。

**11-13 dump 是怎么来的：** 把 `aihot-20261014.dump` 恢复到 WSL 的 PG 17.12，
再用当前代码补跑 18 条迁移（61 → 79），随后 `pg_dump -Fc` 导出。
导出前删掉了 worker 误启动时补出的 3 份报告（`daily:2026-10-15`、`weekly:2026-W42`、
`monthly:2026-10`）——它们的依据是缺失的 10-15 之后数据，留着会误导读者。
所以这份 dump 的业务数据与 10-14 那份完全一致，差别只在 schema 已经是最新的。

## 本地 WSL（当前主部署）

2026-11-13 起线上跑在本地 WSL，用用户级 systemd 管 `regwatch-api/worker/web`，
PG 17 在 5433。完整步骤见 `docs/deploy-local.md`，最短路径：

```bash
# 1. 代码（仓库里已有 deploy/systemd-user 和 scripts）
git clone aihot-847043c.bundle /home/zkye/project/regwatch
# 或直接复用 /home/zkye/project/regwatch

# 2. 配置
cp aihot.env      /home/zkye/project/regwatch/.env
cp .env.local     /home/zkye/project/regwatch/.env.local
chmod 600         /home/zkye/project/regwatch/.env*

# 3. 库
createdb -h 127.0.0.1 -p 5433 -U aihot aihot
pg_restore -h 127.0.0.1 -p 5433 -U aihot -d aihot \
  --no-owner --role=aihot --exit-on-error aihot-20261113-1154.dump

# 4. Node 用 nvm default（>=24.22.1），不要另装系统 Node
# 5. unit
cp deploy/systemd-user/* ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now regwatch.target regwatch-backup.timer
```

worker 默认不会启动（`ConditionPathExists=/home/zkye/project/regwatch/.worker-enabled`），
避免在采集/模型关闭时补跑缺失期间的日报。

## 恢复顺序（新 Pod）

### 0. 先校验本机包
```powershell
cd E:\project\AIHOT\server-backups\20261113
Get-Content SHA256SUMS.txt | ForEach-Object {
  $h,$f = $_ -split '  ',2
  if ((Get-FileHash $f -Algorithm SHA256).Hash.ToLower() -ne $h) { throw "BAD $f" }
}
```

### 1. 装 PG 17.4（版本必须与 dump 一致）

dump 头是 `17.4 (Ubuntu 17.4-1.pgdg20.04+2)`。新 Pod 若还是 Ubuntu 20.04：

```bash
# 20.04 的 PGDG 已归档；源码编译最稳（需要 bison/flex）
apt-get update && apt-get install -y bison flex zlib1g-dev
cd /tmp
curl -fsSLO https://ftp.postgresql.org/pub/source/v17.4/postgresql-17.4.tar.bz2
tar xf postgresql-17.4.tar.bz2 && cd postgresql-17.4
./configure --prefix=/home/arc-yy17196/project/regwatch/pgsql \
  --with-zlib --without-readline --without-icu --without-openssl
make -j16 && make install
```

如果新 Pod 是 22.04/24.04，也可以直接用 PGDG 装 `postgresql-17`，只要版本是 17.x。

### 2. 初始化并启动

PG 不能以 root 运行。新建系统用户（数据目录放 NFS 持久盘）：

```bash
useradd -m -s /bin/bash regwatch || true
mkdir -p /home/arc-yy17196/project/regwatch/pgdata
chown -R regwatch:regwatch /home/arc-yy17196/project/regwatch
su - regwatch -c '/home/arc-yy17196/project/regwatch/pgsql/bin/initdb \
  -D /home/arc-yy17196/project/regwatch/pgdata -E UTF8 --locale=C'
su - regwatch -c '/home/arc-yy17196/project/regwatch/pgsql/bin/pg_ctl \
  -D /home/arc-yy17196/project/regwatch/pgdata \
  -l /home/arc-yy17196/project/regwatch/pg.log \
  -o "-p 5432 -c listen_addresses=127.0.0.1" start'
```

> 用户说 PG 安装位置可以不持久，只要备份持久；这里仍放 NFS，省一次重装。
> 如果 NFS 上跑 PG 有问题，把 `pgdata` 换到 `/var/lib/regwatch`，备份仍写 NFS。

### 3. 建角色和库

从 `.env` 取密码，不要打印：

```bash
set -a; . /home/arc-yy17196/project/regwatch/.env; set +a
PGPASSWORD="$POSTGRES_PASSWORD" psql -h 127.0.0.1 -U postgres -d postgres \
  -c "CREATE ROLE aihot LOGIN PASSWORD '$POSTGRES_PASSWORD'" \
  -c "CREATE DATABASE aihot OWNER aihot"
```

（若 `.env` 的 `DATABASE_URL` 用户名/密码与 `POSTGRES_PASSWORD` 不同，以 `DATABASE_URL` 为准。）

### 4. 恢复 dump

优先用 11-13 那份（79 条迁移，PG 17.12 导出）：

```bash
PGPASSWORD=... pg_restore -h 127.0.0.1 -U aihot -d aihot \
  --no-owner --role=aihot --exit-on-error \
  /home/arc-yy17196/project/regwatch/aihot-20261113-1154.dump
```

如果只有 10-14 那份原始 dump（61 条迁移，PG 17.4 导出），也可以：

```bash
PGPASSWORD=... pg_restore -h 127.0.0.1 -U aihot -d aihot \
  --no-owner --role=aihot --exit-on-error \
  /home/arc-yy17196/project/regwatch/aihot-20261014.dump
```

恢复后先记下 dump 里的迁移进度：

```bash
psql -h 127.0.0.1 -U aihot -d aihot -Atc \
  "select count(*), max(name) from schema_migrations"
```

11-13 那份应为 **79**，10-14 那份为 **61**。

### 5. 用当前代码补 10-14 之后的迁移（只在用了 10-14 旧 dump 时需要）

```bash
cd /home/arc-yy17196/project/regwatch
DATABASE_URL='postgres://aihot:...@127.0.0.1:5432/aihot' node scripts/migrate.ts
```

迁移器会按文件名补跑 `schema_migrations` 里没有的那些；**不要手工改历史迁移文件**。

### 6. 验证 schema 正确（关键）

```bash
# 从零建一个对照库
createdb -h 127.0.0.1 -U postgres -O aihot aihot_schema_check
DATABASE_URL='postgres://aihot:...@127.0.0.1:5432/aihot_schema_check' node scripts/migrate.ts

# 两边只导 schema，逐表对比
pg_dump -h 127.0.0.1 -U postgres --schema-only --no-owner --no-privileges aihot > /tmp/restored.sql
pg_dump -h 127.0.0.1 -U postgres --schema-only --no-owner --no-privileges aihot_schema_check > /tmp/fresh.sql
diff -u /tmp/fresh.sql /tmp/restored.sql
```

`diff` 必须为空（除了 `schema_migrations` 的行数/注释这类非结构差异）。
有差异就停下来，先查是哪条迁移在旧数据上没生效，**不要启动服务**。

### 7. 启动与验收

```bash
cd /home/arc-yy17196/project/regwatch
npm install
npm run build -w @aihot/web
node scripts/seed.ts          # 信源以 industry/sources.json 为准，重复执行是幂等的
bash start.sh                 # 三个进程都要带 NODE_ENV=production
curl -s http://127.0.0.1:3001/api/health
node scripts/smoke.ts --base http://127.0.0.1:3000
```

### 8. 备份（这次必须一起做）

本地 WSL 主部署的备份由 systemd timer 完成，全在 WSL 里：

- 每天 04:10：`regwatch-backup.timer` → `scripts/backup-local.sh`
  - `pg_dump -Fc` 到 `~/regwatch-backups/`
  - `pg_restore --list` 验证
  - 复制到 `F:\backup\09-regwatch\`，重写 `SHA256SUMS.txt`
  - WSL 和 F: 各保留最新 **7 份**（F: 不可用时只保留 WSL 那份并打警告）

切回远程服务器后，本地 timer 失效，要换成：

- 服务器侧：`packages/backend/src/operations/backup.ts` 的 `backup` 任务，
  配好 `DB_BACKUP_STORE_*` 后按 daily/weekly/monthly 上传到 COS；
  或按 `DEPLOYMENT.md` 里的 `backup.sh` 手动 `pg_dump`。
- 本机侧：需要留一份的话，用 `scp` 把最新 dump 拉回
  `F:\backup\09-regwatch\`，校验 `PGDMP` 头和 SHA256。
