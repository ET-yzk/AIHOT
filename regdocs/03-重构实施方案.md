| 项 | 值 |

> **本文档的性质**：把五阶段设计落到可执行的交付序列。与 v1.0 的根本差异是**不再做绞杀者式的双跑影子接管**——因为核心策略改为"替换 `industry/` 包 + 模块增强"，大部分阶段是**增量交付**而非替换既有系统。每一步仍然需要：交付什么 / 验收条件 / 依赖 / 回滚方式，但不再需要"影子跑两周再切"。

## 1 全局规则

| # | 规则 | 理由 |
|---|---|---|
| G1 | **`industry/` 包是唯一行业定制面**；核心管线代码（`packages/backend/src/`）的改动必须是追加式的（新模块、新端点），不改既有函数签名 | 保证上游 rebase 可合并（DES §8） |
| G2 | **模块间零共享数据库写入**：法规模块、原文库模块、解读模块各自通过 HTTP API 或同进程内的模块边界函数交互，不直写对方的表 | DES §1.3 写路径铁律 |
| G3 | **Python 永不直插平台数据库**；RegPilot 与平台之间只走 HTTP/JSON | DES §1.3 |
| G4 | **存量数据违规只报告不阻断**：导入期守卫出校验报告，约束在违规清零后单独启用 | DES §9.3；fail-closed 是运行期偏好，迁移期会自我拒绝 |
| G5 | **测试去污染先于行业包替换**：把 29 个测试里硬编码的示例行业分类/标签换成从 `industry/` 包导入的值，独立 PR，先让套件全绿 | 否则换行业包后无法区分真回归与示例污染 |
| G6 | **黄金语料在阶段二启动前交付**：把 regwatch 的守卫语义（精度降级、链接覆盖、子项吞并等）变成表驱动的可执行测试 | 这是规则从口述历史变成可执行规格的唯一机会 |
| G7 | **每一阶段的 DoD 必须含**：验收脚本输出留档 + 回滚方式实测一次 | 没演练过的回滚不是回滚 |
| G8 | **删除优于关闭**：AIHOT 自带的模型榜单与额度监控模块直接删除，不保留配置关闭 | 关掉的模块在 rebase 时仍会产生冲突；删除是干净的一次性操作 |

## 5 阶段三：原文库（新模块）

**目标**：原文 PDF 入库、解析、站内检索、与法规记录关联。核心策略：**字节在一侧，索引在另一侧**。

## 9 里程碑与工作量

人力按 1 名全职估算；日历时间按 30–40% 有效产能打折。

| 里程碑 | 包含 | 有效人日 | 日历周 | 出口条件 |
|---|---|---|---|---|
| **M1 行业动态** | 阶段一全部 | 20–28 | 4–6 | 门户展示车载内容；标签筛选可用；报告自动生成；信源健康度可监控 |
| **M2 法规动态** | 阶段二全部（含黄金语料） | 30–40 | 8–10 | 法规元数据追踪可用；状态机守卫生效；评审队列可用；法规页面可访问 |
| **M3 原文库** | 阶段三全部 | 20–28 | 6–8 | 原文可上传/解析/检索；WeKnora 推送可用；法规页关联原文 |
| **M4 解读·对比·问答** | 阶段四全部 | 28–36 | 8–10 | 三个模块可用；双向链接可跳转；引用可回链 |
| **M5 个性化** | 阶段五全部 | 12–18 | 4–6 | 角色配置可用；个性化推送可用 |
| 合计 | | **约 110–150 人日** | **约 30–40 周** | |

**关键路径**：M1 → M2 → M3 → M4。M2 是风险最高的阶段（存量数据导入 + 守卫语义形式化），它的日历时间是刻意留长的。

**与 v1.0 的差异**：v1.0 是 148–202 人日 / 44–56 周（绞杀者模式，含大量双跑影子等待期）；v2.0 是 110–150 人日 / 30–40 周（增量交付，无双跑等待）。节省主要来自：不做采集双跑（阶段一直接替换行业包）、不做落表双写（阶段二直接写 Postgres，飞书投影是单向派生）、不做卡片渲染器移植（迁移期保持 RegPilot 渲染）。

**可交付中间价值**：M1 完 = 车载行业资讯流可用，已有独立价值；M2 完 = 法规追踪与评审可用，合规工作流数字化；M3 完 = 原文库可用，法规原文可检索；M4 完 = 阶段四目标达成，解读/对比/问答可用。
