## 1. 定位与原则

### 1.1 只约束写入，不动既成事实

| 做 | 不做 |
|---|---|
| 规定每个字段的合法形状、取值来源、空值表达 | 不改表结构、不加不改字段、不重建 Base |
| 规定写入端在落表前做什么校验、归一 | 不把 104 条历史数据一次性回填 |
| 给出一份可机读规则，接进 regpilot | 不要求 regpilot 重跑历史解析流程 |
| 给出一套只读审计口径 | 不允许任何脚本在审计阶段写表 |

理由：表是 104 条在用的业务台账，不是草稿。**大改动的代价是「改坏了没人知道」**，而小步的价值是每一批都能 diff、能回滚、能验收。

### 1.2 三步走（顺序不可颠倒）

| 步 | 做什么 | 产出 | 完成判据 |
|---|---|---|---|
| **① 只读审计** | 现有数据按本文档跑一遍，只读不写 | 违规清单（NDJSON + 摘要） | 能按字段、按级别数出违规条数 |
| **② 约束新增** | 写入端接上 L1 校验，新写入/新修订的记录不再产生违规 | 校验器 + 拒绝日志 | 新写入的违规率 = 0 |
| **③ 存量分批清** | 按 P0 → P1 → P2 逐批修，每批一次 diff | 每批一份变更清单 | 每批验收通过才进下一批 |

**第②步不依赖第③步**：先把闸门装上，脏数据不再增加；存量慢慢清，清不完也不影响页面。

### 1.3 站点侧先做容错，不等清洗

站点（RegWatch 门户）**只读**这张表，不写回。因此：

- 站点不把规范当作前置条件——脏数据在页面上必须能正确显示或明确标注，不能崩、不能丢。
- 站点的容错契约见第 8 节；规范清完之后，这些容错代码仍然保留（防御未来的新脏数据）。

## 2. 三级规则

| 级别 | 含义 | 由谁保证 | 违规时的表现 | 时间点 |
|---|---|---|---|---|
| **L1 必须** | 违反就**不能落表** | regpilot 写入端 | 拒绝写入该条 + 记日志 + 进当日告警摘要；**不静默改值** | 每次 upsert 前 |
| **L2 建议** | 违反**照写**，但记一笔 | regpilot 写入端 | 写告警日志，每日汇总推运维群；人工决定改不改 | 每次 upsert 后 |
| **L3 提示** | 只影响可读性/一致性 | 独立审计脚本 | 进月度报告，按优先级排期 | 每日只读扫描 |

补充两条边界：

- **站点读取端不属于任何一级**，它只做容错（第 8 节）。站点不因数据不合规而 500、不因此隐藏记录。
- **L1 的拒绝不能变成丢数据**：拒绝时该条记录保持原样（不写新值），并把「本次想写什么」记进日志，便于人工补。

## 3. 逐字段规范

约定：反例全部来自 2026-11-17 对 104 条的实测，未经改写。

### 3.1 链接类

|---|---|---|---|---|---|

### 3.3 编号与文本类

| 字段 | 类型 | 规则 | 反例 | 正例 | 级别·位置 |
|---|---|---|---|---|---|
| **法规编号** | text（唯一） | ① 规范化写法；② **缺失不得用标题截断冒充**（X-01，现实现 `title[:60]` 正是反例）；③ 空格统一为半角单空格 | 计划号 `2026271-T-339` 与 `GB/T 41797-2022` 混在同一列（可接受，但需能区分） | `GB/T 41797-2022` / `UN R155` / `EU 2024/1234` / `CNCAP-2024` | **L1** regpilot 写前 |
| **法规全称** | text | 去首尾空格；不用来当编号；≤ 120 字 | 与编号同值 | `CNCAP 中国新车评价规程 2024版` | L2 |
| **核心摘要** | text | 50–100 字；说清「是什么 + 什么时候生效 + 管谁」 | 超出或过短 | `CNCAP 2024 版中国新车评价规程计划于 2024 年 1 月发布、7 月实施……` | **L2**（告警） |

**通用文本规则（所有 text 字段）**

1. 去首尾空白，内部连续空格压成一个。
2. 中文场景用全角括号 `（）`，中英文混排的编号/缩写内部用半角 `()`；同一字段不混用。
3. 不用换行符做排版；一格一段。
4. 不写「见上」「同上」「待补」。

### 3.4 枚举类

**共同规则**：取值必须来自该字段的选项（词表）；**词表外的新值不允许直接写入**——要么先由人把新值加进选项，要么归并到已有值。历史上 BR-22 就栽在这里：字段定义 7 个选项、实际存储 6 个，「待评审」写不进去，整批记录报 `not_found`。

| 字段 | 词表来源 | 当前实测 | 规则 | 级别 |
|---|---|---|---|---|
| **地区** | 字段选项（28 项：8 大区 + 20 国家） | 只用了 10 个值 | 取**最小适用地区**：明确到国家就写国家，多国联盟才写大区 | L1 |
| **业务分类** | 字段选项（8 项：DMS/OMS/脱敏/信息安全/哨兵/ADAS/AVM/功能安全） | 102/104 有值，出现词表外 **`底层`** × 1 | 涉及就标，顺序=法规中的优先级；**纯硬件法规可为空** | **L1** |
| **产品功能** | 字段选项（多选，实际 ≥40 项） | 97/104 有值，7 条为空 | 先命中一级业务分类，再从摘要/原文摘功能词 | L1 |
| **适用国家** | 字段选项（22 项） | 88/104 有值 | 与「地区」不是同一维度：地区=法规最小适用范围，适用国家=实际适用清单 | L1 |
| **法规认证类型** | 字段选项（7 项，含 `待评审`） | 104/104 有值，`待评审`**从未出现** | 判不出时**写「待评审」**，不要留空、不要自造 | **L1** |
| **生命周期阶段** | 字段选项（6 项，有序） | 正式发布 78 / 征求意见稿 14 / 已修订 8 / 已废止 3 / 报批稿 1 | **只进不退**（状态机）；允许 已修订 → 已废止 | L1 |
| **原文入库** | 字段选项（3 项） | 已入库 81 / 未入库 16 / 受限 7 | 与原文库对账可自动推导，不手工填 | L2 |
| **原文获取方式** | 字段选项（6 项） | 只用了 4 项（需注册 / 第三方摘要 从未出现） | 判不出写 `暂无原文`，不留空 | L2 |
| **订阅状态** | 字段选项（3 项） | 稳定低频 60 / 高频监控 44，`待评审` 0 | **受保护字段**：人工置为后两项后自动流程不得改回（BR-18） | L1 |
| **解读状态** | 字段选项（3 项） | 未认领 102 / 已沉淀 2 | 认领互斥 | L2 |
| **印证状态** | **派生值**，不是人工填 | 104/104 全「已印证」 | 由信源层级派生：T1→已印证、T2→待印证、T3→待核实 | **L2** |

**`底层` 的处置建议（不要静默丢弃）**，三选一，由业务方拍板：

1. **进词表**：如果「底层」确有独立语义（如底层操作系统/基础软件），把它加进业务分类选项，并同步更新 `regdocs/附录B` §4.1 与 regpilot 的 `table_schema.json`。
2. **归并**：如果它只是「功能安全」或「技术落地」的另一种说法，归并到对应项，并在该条记录写一条变更说明。
3. **降级到标签**：如果它跨多个一级分类，放进「产品功能」而不是「业务分类」。

**在拍板之前**：这条记录保持原样，站点原样显示（第 8 节），不丢。

## 4. 必填与条件必填矩阵

**恒必填（13 项）**：法规编号、法规全称、地区、生命周期阶段、核心摘要、影响评估、印证状态、原文链接、原文入库、原文获取方式、订阅状态、法规认证类型、解读状态、上次检查日期。

**条件必填**（沿用附录B §1.1）：

| 当 | 必填 | 判据 |
|---|---|---|
| 生命周期阶段 = `已修订` | 修订日期 | 缺 → L1 拒写 |
| 生命周期阶段 = `正式发布` | 发布日期 | 缺 → L1 拒写 |
| 生命周期阶段 = `征求意见稿` | 征求意见截止日期 | 缺 → L1 拒写 |
| 业务分类非「纯硬件法规」 | 业务分类至少 1 项 | 纯硬件为空需在摘要里说明 |
| 信源T1-官方 为空 | 不允许 | T1 是采信依据，必须有 |

**选填**：适用国家、适用车型、印证策略、信源T2/T3、报批稿截止日期、认领人、修订日期（非已修订时）。

**空值规则（全局）**：**留空**。不得写 `-`、`--`、`暂无`、`待定`、`N/A`、`无`、`空`。
理由：这些占位串会让「筛选=空」失效，也会被站点当成真实取值显示出来。

## 6. 存量清洗：优先级与做法

**总原则**：**逐批 diff，不一次性回填**。每批产出「record_id / 字段 / 旧值 / 新值 / 依据」四列，人工确认后才写；每批写完立刻重跑审计对比前后违规数。

### P0 — 原文链接与日期（先做，影响页面可用性）

| 项 | 内容 |
|---|---|
| 判据 | 原文链接不满足「单 URL 或 `[标题](URL)`」、或含多个链接、或尾随标点；日期字段不是合法 `YYYY-MM-DD` |
| 范围 | 104 条全量扫描；实测原文链接 104/104 有值，抽样 3 条均为 Markdown |
| 做法 | 脚本只**提议**新值（把 Markdown 拆成 URL 或规范成 `[短标题](URL)`），不自动写；人工过一遍 diff |
| 验收 | 重跑审计：P0 违规 = 0；抽 10 条页面显示与原表一致 |
| 风险 | 把「标签=URL」的冗余写法改成裸 URL 会丢失标题语义 → 优先保留有意义的标题 |

### P1 — 枚举一致性

| 项 | 内容 |
|---|---|
| 判据 | 取值不在字段选项内；同义写法共存 |
| 已知 | 业务分类 `底层` × 1；发布机构 6 种写法；印证状态 104 条全「已印证」但规则要求派生 |
| 做法 | 先出「词表外取值清单」，由业务方拍板进词表还是归并（第 3.4 节三选一），再批量改；发布机构按 `alias_map` 一次性归一 |
| 验收 | 词表外取值 = 0（或全部登记进白名单并写明理由）；发布机构取值种类从 25 种降到 ≤ 21 种 |
| 风险 | 归并会丢信息 → 「归口」这类信息保留在后缀里，不塞进其他字段 |

### P2 — 文本质量

| 项 | 内容 |
|---|---|
| 判据 | 核心摘要不在 50–100 字；影响评估超 300 字或含内部信息；括号/空格/全半角不统一；上次检查日期停滞超过 30 天 |
| 做法 | 只出清单 + 建议，不强制清零；每次顺带修 |
| 验收 | 违规率下降即可，不设 0 目标 |

### 不做

- 不重跑历史解析批次（成本高、结论不可复核）。
- 不为了「干净」删除任何记录；去掉重复用标记不用删。
- 不在清洗阶段改表结构。

## 7. 审计清单：只读脚本规格

### 7.1 输出什么

**每行一条违规**（NDJSON，便于 diff 和二次处理）：

```json
{
  "run_at": "2026-11-17T03:00:00+08:00",
  "table": { "app_token": "VBcRbUg…", "table_id": "tblMH…", "records": 104, "rev": 795 },
  "record_id": "recvtRFr0xtyfp",
  "code": "CNCAP-2024",
  "field": "原文链接",
  "level": "P0",
  "rule": "link.single_url_or_markdown",
  "value": "[中汽测评|C-NCAP 技术规程（含 2024 年版管理规则）](https://www.c-ncap.org.cn/cncap/rules)",
  "suggestion": "改为 https://www.c-ncap.org.cn/cncap/rules 或 [C-NCAP 技术规程](https://www.c-ncap.org.cn/cncap/rules)"
}
```

**另出一份摘要**（Markdown，直接推群）：

| 段落 | 内容 |
|---|---|
| 总量 | 记录数、扫描字段数、违规条数、按级别分布 |
| 按字段 TOP | 字段 → 违规条数（降序），标出本日新增违规 |
| 按规则 TOP | 规则 id → 条数 |
| 新增 | 与上一次审计的差集（只列新增的 record_id + 字段） |
| 基线漂移 | 字段选项集合变化、词表外新值首次出现 |
| 建议动作 | 前 3 条，带 record_id |

**要求**：
1. 全程只读（只调 `records/search`，不调任何写接口）。
2. 幂等：同一天重跑结果一致，带 `run_at` 方便比对。
3. 保留最近 90 天，按 `audit/source-table-YYYY-MM-DD.ndjson` 存放（不进 git）。

### 7.2 regpilot 侧怎么跑

| 时机 | 动作 | 产物 |
|---|---|---|
| 每次 upsert 前 | 对**本次要写的那条**跑 L1 规则 | 不通过 → 拒写 + 日志 |
| 每次 upsert 后 | 跑 L2 规则 | 通过与否都写告警日志 |
| 每日 03:00（cron） | 全表只读审计 | `audit/source-table-<date>.ndjson` + 摘要 |
| 每日 03:30 | 摘要推运维群（无新增违规时只发一行「今日无新增」） | 群消息 |
| 每月 1 日 | 汇总 P0/P1/P2 存量趋势，附本批建议动作 | 月报 |

**失败处理**：审计失败不影响写入链路；失败原因进当日告警。审计连续 2 天失败要升级为告警。

## 8. 站点读取端的容错契约（给开发看）

站点**只读**、不写回，且不等规范清完。以下行为在实现时必须保证：

| 情况 | 站点行为 |
|---|---|
| 原文链接是 `[标题](URL)` | 解析出 URL 与标题；标题为空或等于 URL 时只显示域名或「打开原文」 |
| 原文链接是裸 URL | 直接可点 |
| 原文链接解析失败 | 原文当纯文本显示，标「链接格式待修」，**不给可点**、不跳到错误地址 |
| 枚举出现词表外的值（如 `底层`） | **原样显示**，不丢弃、不映射到相似项；页面照常可筛到它 |
| 日期无法解析 | 原样显示并标「格式待修」，不猜、不补全 |
| 日期为月精度留空 | 显示「—」，不显示「未公开」 |
| 任何字段为空 / 占位串残留 | 显示「—」；占位串（`暂无`、`待定`、`-`）按空处理 |
| 出现未知的新字段 | 进详情页「其他字段」区，不丢 |
| 同步失败 | 显示上次成功同步时间 + 黄色提示条，**不显示半份数据** |

## 9. 变更与版本

| 变更 | 做法 |
|---|---|
| 新增字段 | 本文档加一行 + JSON 加一项 + 站点「其他字段」自动兜住，无需同步发版 |
