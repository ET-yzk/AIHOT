## 0 结论先行

- 形态：桌面「表格优先」+ 手机「卡片」+ **独立详情页**。不做主从分栏的空转预览，因为需求本身就是「点进去看全」。
- 视觉：完全沿用站点现有的暖纸底 / 墨色字 / 酒红强调 / 发丝线 / 六档圆角 / 无渐变。不新造一套设计语言。
- 交互：筛选即时生效并写进 URL；整行可点；返回保留筛选；手机筛选走底部抽屉。
- 一句话：这页读起来应该像一张**排版讲究的台账**，不是一张电子表格截图。

## 1 三个方向的比较（团队发散后收敛）

| | A 表格优先 | B 卡片目录 | C 主从分栏 |
|---|---|---|---|
| 长什么样 | 一张密排的表，行高 44px，字段对齐 | 卡片瀑布流，按地区/机构分组 | 左侧列表 320px，右侧详情常驻 |
| 优点 | 信息密度最高，扫读快；31 字段里 7–8 个能横向对齐比较；最像台账 | 好逛，适合探索和第一次接触 | 切换快，不跳页 |
| 缺点 | 手机不适用；字段多时要列选择 | 密度低，104 条要滚很久；比较困难 | 右侧宽度不够展示 31 字段，还得跳页；等于多写一套 |
| 对需求的契合 | 高（读者是来找具体法规的） | 中 | 低（需求要的就是详情页） |
| 结论 | **桌面采用** | **手机采用** | 不采用 |

**为什么不是 C**：主从分栏的价值是「不离开列表就能预览」，但本需求的正文是 31 个字段，侧栏放不下，最终仍要跳详情页；那等于为一屏预览多写一套渲染与状态。**为什么 B 不做桌面**：104 条按卡片排，一屏只看得见 6 条，找 GB/T 41797 仍要靠搜索，与表格相比没有增益。

**讨论中保留的两个细节**：① 表格里「业务分类」用 chip 而不是纯文本，因为它是筛选入口（FR-ST-05）；② 编号用等宽字体，让 GB/T 与 GB 在视觉上先对齐，扫读更快。

## 2 信息架构与路由

    专栏（侧栏）
    └── 法规信源        /sources            总览
        └── 详情        /sources/<slug>     例：/sources/gb-t-41797-2022

- slug 由法规编号生成（小写、非字母数字转连字符）：GB/T 41797-2022 → gb-t-41797-2022；编号为空时用 record_id。
- 详情页 **noindex**：内网台账不进搜索引擎，也不进 sitemap。
- 与「法规追踪」（/regulations）并存：侧栏里一前一后，名字必须能区分——一个是「追踪」（动态资讯），一个是「信源」（台账）。

**为什么这样排**：来看这部法规的人，要的是「它是什么、什么时候生效、管哪些车、归哪类、原文在哪」——这些必须在第一屏。信源层级（T1/T2/T3）、印证状态、原文入库、订阅读法、认领人、创建与检查时间，只有维护这张表的人才关心；它们不删，但折叠进「元数据」，默认收起，展开后仍按组有秩序。

详情页用站点现有的阅读模板（760px 正文列 + 右侧信息栏），与站内文章页一致。

## 4 视觉规范

全部取自 apps/web/app/app.css 的语义 token，**不新增颜色**。

| 用途 | token | 浅色 | 深色 |
|---|---|---|---|
| 页面底 | --bg | #f8f4ea | #0f0f0c |
| 卡片/表格底 | --surface | #fffdf8 | #151511 |
| 侧栏底 | --sidebar | #fbf7ee | #11110e |
| 正文墨色 | --ink | #211a12 | #ede7dc |
| 次级文字 | --ink-3 | #6b5b4a | #b0a28c |
| 发丝线 | --line | #e4daca | rgba(237,231,220,.1) |
| 强调 | --accent | #7a3e2e | #d9a15f |
| 已废止/警示 | --hot | #a33a2e | #d97a5f |
| 已入库/通过 | --ok | #3f6b4e | #8fbf8a |

- **字体**：正文 Ubuntu / 系统无衬线栈，回退 PingFang SC、Microsoft YaHei；编号与日期用等宽字体；详情页大标题用衬线，与站点阅读字体一致。
- **字号**：页标题 24/1.3；表格正文 13.5；表头 12、字距 0.06em；详情节标题 13 加粗；正文 15/1.75。
- **圆角**：只用 5 / 8 / 10 / 12 / 14 / 16 与 pill 六档，不出现任意值。
- **分隔**：只用 1px 发丝线，不用阴影区分区块；表格行悬停用浅底。
- **生命周期徽章**：正式发布 → ok；征求意见稿与报批稿 → amber；已修订 → accent；已废止 → hot；起草中 → neutral。

## 5 交互规范

| 交互 | 规则 |
|---|---|
| 搜索 | 输入即筛（250ms 防抖），多词 AND；命中编号/全称/摘要/发布机构 |
| 筛选 | 侧滑面板（桌面）或底部抽屉（手机）；同组多选 OR，跨组 AND；面板底部「清除」与「查看 N 条结果」 |
| 筛选回显 | 结果上方一行 chip，点 × 移除单个，右侧「清除全部」 |
| 排序 | 下拉四选一；无值的行永远排在最后，不参与「最早」排序 |
| 列选择 | 桌面「列」按钮 → 面板勾选；只影响展示，不影响筛选；本机记住 |
| 进详情 | 整行可点 + Enter；悬停时行底变色、编号加下划线 |
| 返回 | 「‹ 返回法规信源」回到列表，**筛选、排序、页码、滚动位置都保留** |
| 复制 | 「复制编号」「复制链接」用站点已有的剪贴板封装，成功给 1.5 秒提示 |
| 原文 | 新窗口打开；Markdown 写法的链接解析后只显示标题 |
| 键盘 | Tab 走行；Enter 进详情；Esc 关面板 |
| 分页 | 默认每页 15 条，可选 15 / 30 / 50；落在 URL（page、size），翻页回到顶部；筛选与搜索变化时回到第 1 页 |
| 同步状态点 | 页脚「信源同步于」左侧一个 7px 圆点，**缓慢呼吸**（2.8s 一圈，幅度克制）：绿 = 最近一次成功，红 = 最近一次失败。悬停 / 键盘聚焦显示最近 5 次同步（时间 + 成功或失败 + 条数）与当前频率 |
| 元数据 | 详情页底部折叠区，默认收起；标题写明里面是什么，让人能判断要不要展开 |

## 6 状态设计

| 状态 | 触发 | 界面 |
|---|---|---|
| 加载 | 切换筛选/分页时 | 表格整体 0.5 透明 + 顶部 2px 进度条，不闪白 |
| 无结果 | 筛选/搜索为空 | 居中空态：「没有符合条件的法规」+ 两个按钮：清除筛选、看全部 |
| 首次无数据 | 从未同步成功 | 说明卡：数据从飞书同步，管理员可触发一次同步；附命令 |
| 同步失败 | 权限失效/网络失败 | **不做顶部横幅**：页脚圆点转红，左侧文案改成「本次同步失败 · 上次成功 11-17 10:23」并整行转红；详情原因在悬停的最近 5 次里 |
| 字段为空 | 单元格无值 | 显示「—」，不显示空白、不猜值 |
| 同步状态 | 最近一次成功 / 失败 | 页脚圆点绿 / 红；失败时同一行文案换成「本次同步失败 · 上次成功 X」，不加横幅、不遮挡内容 |

## 7 响应式

| 断点 | 布局 |
|---|---|
| ≥ 1176px | 侧栏 + 全宽表格 + 右侧信息栏（详情） |
| 700–1176px | 侧栏收为图标条，表格保留，768px 起隐藏次要列 |
| < 700px | 无侧栏，手机壳：卡片列表 + 顶部筛选条；筛选进底部抽屉；详情单列、节标题吸顶 |

卡片字段优先级：编号 + 全称 + 生命周期 + 业务分类 → 发布/实施日期 → 发布机构。

分页在手机上不摆页码：只留「共 N 条 · 每页条数 · ‹ 3 / 7 ›」，一行放得下；页脚带换成两行：左边状态、右边数据源，圆点始终紧贴「信源同步于」。

页面里的链接**没有下划线**（站点全局 `a{text-decoration:none}`）：靠颜色区分，悬停才出现在正文里；下拉框用自绘箭头，不用浏览器默认样式。

## 8 可访问性

- 表头 aria-sort 反映当前排序；可点行 tabindex=0。
- 可点元素都有 focus-visible 描边（2px accent，偏移 2px）。
- 徽章不只靠颜色传达状态，文字必须可读。
- 正文与背景对比度 ≥ 4.5:1（--ink 对 --bg 约 13:1，--ink-3 约 5.2:1）。
- 抽屉与面板用 role=dialog + aria-modal，Esc 关闭，焦点回到触发按钮。

## 9 Demo 说明

demo/index.html：单文件、不联网、双击即开。

- **数据**：10 条真实记录（取自 2026-11-17 的 104 条），特意包含 Markdown 原文链接、词表外的「底层」、缺失的发布日期、长的影响评估。
- **可操作**：搜索、筛选、排序、列选择、点行进详情、返回保留状态、明暗切换、桌面/手机宽度、模拟同步失败。
- **是示意的地方**：数据是 2026-11-17 的真实 104 条导出（分页、筛选、搜索都跑在真实数据上）；「模拟同步失败」按钮造一个失败的同步；复制按钮不写剪贴板；侧栏其他入口不跳转；「手机 390px」是容器模拟而非断点（断点 < 700px 见 §7）。
- **已定稿的地方**：字段分组、徽章语义、字号与间距、空态与失败态文案、筛选与排序的交互方式；详情页覆盖全部 31 个字段（含修订日期、报批稿截止、印证策略、信源 T3、上次检查、创建时间、认领人）。
- **评审后要做的**：确认形态 A + 手机卡片，再按 03-实现方案.md 落进真实页面。

> Demo 是一次性的：它回答「这页该长什么样」，答案落进 03-实现方案.md 与真实页面后，Demo 留在 docs/implement/source-table/demo/ 作为设计依据，不进产物代码。
